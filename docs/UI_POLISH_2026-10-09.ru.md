Регрессионные проверки покрывают сохранение владельца экрана и черновика при смене трёх размеров, быстрое переключение вкладок, независимое сохранение состояния разделов, восстановление выбранного подраздела Android/Desktop и отсутствие покадровой рекомпозиции содержимого от новой анимации.

Скриншоты общей UI-композиции: светлая/тёмная темы, ширины 320, 360, 760, 1440; окно высотой 650; увеличение шрифта до 130% на ширине 320. Дополнительно проверяются существующие экраны выбора модели, истории, параметров, улучшения и GitHub. Desktop проверяется отдельным запуском и снимками окна при resize. Эмулятор и computer-use не нужны.

Проверка числа рекомпозиций не является измерением FPS. Для подтверждения плавности на конкретном Android-устройстве требуется замер времени кадров на устройстве. Реальную синхронизацию личного репозитория можно проверить после его настройки; текущий редизайн не меняет её протокол.

HTML-импорт остаётся только в Desktop debug. Обычное создание промпта сохраняет его локально; GitHub остаётся отдельной ручной синхронизацией личных записей.

## Проверка модели

Откройте «Настройки → Модели → Настроить» у нужного профиля. Загрузите список моделей или введите ID вручную, выберите модель и нажмите «Проверить доступность модели». Используются адрес, ключ и модель из текущей формы. Для применения профиля к чату нажмите «Сохранить и использовать». Отправляется только `Reply OK.` с лимитом 16 выходных токенов, без истории и системного промпта. Для официальных OpenAI/OpenRouter используется `max_completion_tokens`, для остальных совместимых API — `max_tokens`. Поле лимита сверено с [официальным OpenAI API](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) и [OpenRouter API](https://openrouter.ai/docs/api/api-reference/chat/create-a-chat-completion).

Различаются неподходящий ключ (401), баланс (402), отсутствие доступа (403), модель/адрес (404), лимит запросов (429), отклонённый формат проверки (400/422), другие HTTP-ошибки, таймаут и некорректный ответ. Текст ответов сервера и ключи не показываются. Положительный результат подтверждает доступ для короткого текстового запроса на момент проверки; он не проверяет все возможности модели и полный объём контекста.

Тесты HTTP используют реальные локальные серверы Android/OkHttp и Desktop/Ktor. Дополнительно проверены отмена, двойное нажатие, сброс результата при смене модели и проверка несохранённого профиля без изменения активного провайдера. Проверка не обращается к хранилищу чатов. Реальный тест включается только явным `CHECK_MODEL_AVAILABILITY=1`; он использует системный ключ OpenRouter и одну бесплатную модель, без изменения сохранённых профилей.
