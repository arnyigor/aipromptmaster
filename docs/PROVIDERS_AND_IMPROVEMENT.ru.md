# Провайдеры и улучшение промпта

## Управление подключениями

В настройках Android и Desktop откройте «Провайдеры LLM». OpenRouter сохранён как основной встроенный профиль. Его прежний ключ подхватывается при переходе к профилям.

1. Выберите шаблон OpenAI, LM Studio, Ollama или «Свой сервер».
2. Задайте имя и базовый адрес API, включая `/v1`, если сервер его использует. Для облачного сервиса укажите его собственный ключ; для локального сервера можно отключить требование ключа.
3. Нажмите проверку соединения: приложение запросит список моделей, без генерации текста. Найдите модель через поиск или введите ID вручную.
4. «Сохранить и использовать» сохранит профиль и сделает его активным. Переключение между сохранёнными профилями выполняется кнопкой «Использовать».

Ключ и модель хранятся отдельно для каждого профиля. Смена адреса в редакторе очищает ключ. Проверка соединения не сохраняет черновик и не переключает активного провайдера. Встроенный OpenRouter нельзя удалить или заменить другим адресом; для другого сервиса создайте отдельный профиль.

Поддерживается протокол OpenAI-совместимых `/models` и `/chat/completions`, включая потоковый ответ. Нативные API других форматов требуют отдельного адаптера. Локальные шаблоны основаны на документации [LM Studio](https://lmstudio.ai/docs/developer/openai-compat/models) и [Ollama](https://github.com/ollama/ollama/blob/main/docs/api/openai-compatibility.mdx).

На Desktop `localhost` означает этот компьютер. На телефоне укажите IP компьютера в локальной сети; сервер должен принимать подключения с телефона. В стандартном Android Emulator адрес компьютера — `10.0.2.2`, например `http://10.0.2.2:1234/v1`. Явно заданный локальный HTTP поддерживается; облачные шаблоны используют HTTPS.

Android хранит профили в EncryptedSharedPreferences, исключённых из облачного backup и переноса устройства. Desktop использует существующее зашифрованное хранилище настроек. Ключи маскируются в интерфейсе и не включаются в диагностическое представление профиля. Отдельный HTTP-клиент не ведёт журнал запросов и не следует перенаправлениям.

## Улучшение промпта

На Android откройте редактор промпта и нажмите «Улучшить». На Desktop кнопка находится в карточке промпта. Выберите язык RU/EN, модель и пожелания; при необходимости измените температуру, лимит токенов и потоковый режим.

Генерация использует активный профиль из настроек. Предпросмотр можно остановить. Оборванный, пустой или обрезанный по лимиту ответ нельзя применить. «Применить к черновику» меняет только выбранный язык; сохранение промпта выполняется отдельно. Личные поля, переменные, избранное и рейтинг сохраняются.

Мобильный экран занимает всё окно, прокручивается и сохраняет кнопку применения доступной при открытой клавиатуре. Android multi-backstack и свайпы между основными разделами сохранены.

## Проверено 2026-10-01

- Android unit: 37 тестов; общий KMP-модуль: 13 прошли, один архивный acceptance test пропущен без внешнего ZIP.
- Android 12 Emulator: 7 instrumentation tests, включая миграции, провайдеры и применение улучшения; дополнительно повторён тест с включённой экранной клавиатурой.
- Desktop: 151 тест прошёл, 6 пропущены; portable собран.
- HTTP проверен на локальных тестовых серверах: модели, параметры, streaming/non-streaming, отдельный ключ профиля и работа без ключа.
- PNG мобильных экранов просмотрены; проверены запуск приложения и экран настроек с реальной DI.

Платные запросы к внешним провайдерам и пользовательские ключи для проверки не использовались. Общий контроллер профилей находится в `prompt-contract`; Compose UI пока реализован отдельно для двух клиентов.
