## Необходимо исправить в первую очередь

### 1. P1 — незавершённый streaming выглядит завершённым

**Воспроизведено.** Если поток выдаёт `Partial` с `isComplete=false` и затем заканчивается, Desktop LLMInteractor сохраняет ответ со статусом `Sent`. Завершение коллекции само по себе считается успешным.

[LLMInteractor.kt:336](G:/Android/AndroidStudioProjects/aipromptmaster/desktop/shared/src/commonMain/kotlin/com/arny/aiprompts/domain/interactors/LLMInteractor.kt:336), [SSE parser:321](G:/Android/AndroidStudioProjects/aipromptmaster/desktop/shared/src/commonMain/kotlin/com/arny/aiprompts/data/repositories/OpenRouterRepositoryImpl.kt:321).

Дополнительно по коду: SSE parser не требует финального события, понимает только префикс `data: `; JSON ошибки внутри HTTP 200 не имеет отдельной ветки в `StreamingChatResponse`, поэтому событие без choices может быть пропущено. Эти варианты требуют отдельных HTTP-тестов.

**Исправление:** общие события delta/finish/usage/error; явное состояние «Ответ прерван» при EOF без завершения. Сохранить частичный текст, дать повтор. `finish_reason=length` обозначать как обрезанный ответ. Не повторять платный запрос автоматически.

**Критерий:** локальный сервер закрывает HTTP 200 после нескольких чанков; текст сохранён, статус прерван, новая отправка доступна. Отдельно проверить error-событие, `[DONE]`, finish_reason, timeout и Stop.

### 2. P1 — параллельные изменения сессии перезаписывают друг друга

**Воспроизведено.** Rename и обновление system prompt читают старую целую запись, затем независимо пишут её обратно. При двух чтениях до первой записи итог теряет одно изменение.

[ChatSessionRepositoryImpl.kt:80](G:/Android/AndroidStudioProjects/aipromptmaster/desktop/shared/src/commonMain/kotlin/com/arny/aiprompts/data/repositories/ChatSessionRepositoryImpl.kt:80), [обновление system prompt:145](G:/Android/AndroidStudioProjects/aipromptmaster/desktop/shared/src/commonMain/kotlin/com/arny/aiprompts/data/repositories/ChatSessionRepositoryImpl.kt:145).

Контроллер запускает сохранение system prompt/параметров отдельными coroutine. Быстрые действия и ввод могут пересекаться. Воспроизведение сделано на управляемом DAO; частота на реальной Room-базе не измерена.

**Исправление:** SQL UPDATE только соответствующих колонок; объединять изменения связанных параметров; явно определить порядок сохранения текста. Избегать read-modify-write полной строки для независимых полей.

**Критерий:** параллельные rename/system prompt/параметры сохраняют все значения; быстро введённый текст после перезапуска совпадает с последним видимым текстом.

### 3. P1 — для закреплённой модели сессии шапка может показывать другую модель

**Воспроизведено для состояния с `session.modelId != globalModel.id`.** Генерация отдаёт приоритет modelId сессии, а шапка — глобально выбранной модели. Выбор в диалоге меняет глобальную модель, но не закреплённую модель сессии. Новые сессии создаются с null modelId, поэтому дефект условный: он касается сессий с заполненным полем.

[LlmUiState.kt:72](G:/Android/AndroidStudioProjects/aipromptmaster/desktop/shared/src/commonMain/kotlin/com/arny/aiprompts/presentation/features/llm/LlmUiState.kt:72), [генерация:193](G:/Android/AndroidStudioProjects/aipromptmaster/desktop/shared/src/commonMain/kotlin/com/arny/aiprompts/domain/interactors/LLMInteractor.kt:193), [выбор:138](G:/Android/AndroidStudioProjects/aipromptmaster/desktop/shared/src/commonMain/kotlin/com/arny/aiprompts/presentation/features/llm/DefaultLlmComponent.kt:138).

Дополнительное ограничение: сессия не хранит providerId. После смены активного провайдера её modelId будет отправлен на новый endpoint; модели могут быть несовместимы.

**Исправление:** один effective model/provider для шапки, проверки возможностей и запроса. Явно определить «модель этого чата» и «модель по умолчанию»; историю результата подписывать фактически ответившей моделью. Кнопку проверки оставить в настройках.

**Критерий:** закреплённая сессия + другая глобальная модель + смена провайдера. Отображение и запрос совпадают; несовместимое подключение требует явного выбора.

[ChatSidebar.kt:137](G:/Android/AndroidStudioProjects/aipromptmaster/desktop/shared/src/commonMain/kotlin/com/arny/aiprompts/presentation/ui/llm/components/ChatSidebar.kt:137).

**Исправление:** общий диалог с названием чата и последствиями либо корзина/Undo с отложенным окончательным удалением. Не удалять файлы вложений, пока они используются другими сообщениями.

**Критерий:** отмена ничего не удаляет; подтверждение удаляет нужный чат; открытый чат корректно переключается; Undo работает, если выбран такой вариант.

## Исправления поведения и удобства

### 5. P2 — история Desktop не показывает последнее сообщение; архив трудно вернуть

**Подтверждено кодом.** `getAllSessions()` отдаёт сессии с `messages=emptyList()`, а sidebar берёт preview и число токенов из session.messages. Поэтому превью пустое даже при наличии сообщений.

[ChatSessionRepositoryImpl.kt:42](G:/Android/AndroidStudioProjects/aipromptmaster/desktop/shared/src/commonMain/kotlin/com/arny/aiprompts/data/repositories/ChatSessionRepositoryImpl.kt:42), [ChatSidebar.kt:124](G:/Android/AndroidStudioProjects/aipromptmaster/desktop/shared/src/commonMain/kotlin/com/arny/aiprompts/presentation/ui/llm/components/ChatSidebar.kt:124).

Есть DAO/repository unarchive, но проверенный sidebar показывает только активные чаты и не предлагает просмотр архива/восстановление.

**Исправление:** отдельная проекция ChatSummary с последним сообщением, временем и счётчиками одним запросом; раздел архива с восстановлением. Не загружать всю историю каждого чата ради одной строки.

### 6. P2 — полноценный Markdown в чате есть только на Android

**Подтверждено кодом.** Общая поверхность bubble не означает общий рендерер содержимого: Android использует Markdown, Desktop `MessageContent` показывает простой Text.

[ChatMessageCard.kt:294](G:/Android/AndroidStudioProjects/aipromptmaster/desktop/shared/src/commonMain/kotlin/com/arny/aiprompts/presentation/ui/llm/components/ChatMessageCard.kt:294).

**Исправление:** общий рендерер: списки, ссылки, код с копированием, таблицы, выделение текста. Во время streaming обновлять текст без тяжёлого полного разбора на каждый токен.

### 7. P2 — проверка модели и реальная генерация используют разные правила API

**Подтверждено кодом; совместимость конкретных моделей не проверялась.** Новый probe использует max_completion_tokens на официальных OpenAI/OpenRouter endpoint. Реальный Desktop chat DTO и Android improvement всё ещё используют max_tokens; параметры temperature/top_p также передаются без общей политики возможностей модели.

[MultimodalDTOs.kt:16](G:/Android/AndroidStudioProjects/aipromptmaster/desktop/shared/src/commonMain/kotlin/com/arny/aiprompts/data/model/MultimodalDTOs.kt:16), [ProviderHttpSource.kt:31](G:/Android/AndroidStudioProjects/aipromptmaster/app/src/main/java/com/arny/aipromptmaster/data/ProviderHttpSource.kt:31).

Следовательно, «доступна» подтверждает короткий диагностический запрос, но не гарантирует, что реальная генерация с другими параметрами будет принята. OpenAI документирует несовместимость max_tokens с o-series: [официальная спецификация](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).

**Исправление:** общая политика поддерживаемых параметров и построения запросов для проверки/чата/улучшения; передавать только поддерживаемые поля. Не считать все OpenAI-compatible серверы одинаковыми.

### 8. P2 — контекст и вложения ограничены недостаточно

**Подтверждено кодом.** История ограничивается количеством сообщений, не бюджетом токенов конкретной модели. Desktop читает целиком текст/изображение, не делает resize изображения; большое вложение может увеличить память и превысить API limits.

[buildApiContext:453](G:/Android/AndroidStudioProjects/aipromptmaster/desktop/shared/src/commonMain/kotlin/com/arny/aiprompts/domain/interactors/LLMInteractor.kt:453), [PlatformFileHandler:20](G:/Android/AndroidStudioProjects/aipromptmaster/desktop/shared/src/desktopMain/kotlin/com/arny/aiprompts/domain/files/PlatformFileHandler.desktop.kt:20).

**Исправление:** лимит размера до копирования/чтения; resize/компрессия изображений; резерв токенов ответа; оценка контекста с учётом system prompt и вложений; сообщение о сокращении истории. Очистка неиспользуемых вложений. PDF/DOC добавить только при реальной потребности: сейчас Desktop их отклоняет явно.

### 9. P2 — список профилей Desktop может превысить лимит Preferences

**Граница воспроизведена на реальном EncryptedJvmSettings с изолированным delegate.** Все профили сохраняются одним JSON в одном значении. После AES-GCM/Base64 значение увеличивается. JSON с названием из 6200 ASCII-символов уже превышает лимит; приложение не ограничивает длину названия и общее число/размер профилей.

[SettingsRepositoryImpl.kt:94](G:/Android/AndroidStudioProjects/aipromptmaster/desktop/shared/src/commonMain/kotlin/com/arny/aiprompts/data/repositories/SettingsRepositoryImpl.kt:94). Java Preferences ограничивает значение 8192 символами: [Oracle](https://docs.oracle.com/en/java/javase/17/docs/api/java.prefs/java/util/prefs/Preferences.html).

**Исправление:** отдельные значения/надёжный chunked формат с атомарным переключением поколения либо шифрованный файл; валидация размера до сохранения. При отказе старые профили должны остаться доступными.

**Отдельный риск:** EncryptedJvmSettings держит общий изменяемый Cipher на весь экземпляр, без синхронизации. При доступе из нескольких потоков возможны ошибки. Конкурентное воспроизведение не выполнялось. Предпочтительно создавать Cipher на операцию и добавить тест параллельного доступа.

### 10. P2 — личный GitHub требует проверок частичного применения и реального сценария

**Риск, а не доказанная потеря данных.** Apply выполняет remote.write → local.apply → сохранение baseline. Общая атомарная транзакция между GitHub, SQLite и preferences невозможна. Если после успешного PUT падает локальная операция или приложение завершается, стороны временно расходятся; текущее сообщение не различает стадии.

[PersonalVault.kt:159](G:/Android/AndroidStudioProjects/aipromptmaster/prompt-contract/src/commonMain/kotlin/com/arny/promptcontract/PersonalVault.kt:159).

**Исправление:** фиксировать стадии/результат операции, объяснять «GitHub обновлён, локальное применение не завершено», безопасно предлагать повторный preview. Добавить fault-injection после PUT, после local.apply и до baseline. Не пытаться откатывать GitHub вслепую.

**Удобство:** время последней успешной синхронизации, несинхронизированные изменения, обработка истёкшего токена, проверка репозитория/прав, удобный список конфликтов. При десятках длинных конфликтов текущий Column с полными версиями стоит заменить списком и отдельным сравнением. OAuth/device flow и разбиение файла на несколько — необязательные следующие этапы.

Реальная private GitHub синхронизация между двумя клиентами пока не подтверждена: нужен настроенный пользователем репозиторий. Нельзя считать локальные HTTP-тесты эквивалентом этой проверки. Лимит файла 900 КБ осознанный; не требуется немедленно усложнять формат, если личный набор меньше лимита.

## Архитектура и тестирование

Объединены repository и часть UI, но ещё не вся бизнес-логика. Android ChatViewModel/LLMInteractor и Desktop DefaultLlmComponent/LLMInteractor отдельно управляют отправкой, контекстом, retry/edit и ошибками. Именно здесь появляются расхождения, описанные выше.

Предпочтительный следующий шаг: общие контракты ChatState/ChatAction/ChatEvent, модель статусов сообщения, effective provider/model, policy контекста, SSE decoder и request builder. Room/файлы/системное хранилище ключей и навигация остаются адаптерами. Не переносить всё одним большим изменением и не переписывать работающие миграции ради архитектурной чистоты.

Два Gradle root и разные version catalogs увеличивают сопровождение. После исправления поведения полезно свести общие версии и затем рассмотреть единый build. Это техническое улучшение, не условие корректной адаптивности.

Проверки следует усилить:

- Семантические Compose-тесты действий, focus и доступности. PNG generation проверяет рендеринг, но автоматически не доказывает правильную геометрию/кликабельность каждого элемента.
- Полный offline Desktop suite в CI либо явный поддерживаемый набор с объяснением исключений. Сейчас CI запускает длинный вручную перечисленный список классов; новый тест можно забыть включить.
- Скриншоты 320/360/600/840/1440, light/dark, длинные русские названия, fontScale до 2.0, увеличение системного DPI, экранная клавиатура и экранный диктор. Удерживать видимыми действия сохранения/отправки.
- Frame timing, CPU/память при большом чате, streaming и библиотеке из 10 000 записей. Счётчик recomposition не доказывает FPS. На реальном Android устройстве нужен Macrobenchmark FrameTimingMetric: [официальное руководство](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-overview). Desktop в мобильном размере проверяет адаптивность, но не Android IME/insets/lifecycle.
- Надёжный экспорт/восстановление личных промптов и чатов вне GitHub, с отдельной политикой исключения ключей.
