# Личные промпты и GitHub

## Что сохраняется как раньше

Создание и редактирование промпта сохраняют запись в локальной личной библиотеке (`isLocal=true`). Для этого не нужны GitHub, токен или интернет. Настройка GitHub не меняет этот сценарий и сама по себе ничего не отправляет.

Публичный каталог `arnyigor/aiprompts` продолжает обновляться отдельно. В личный репозиторий попадают только личные записи; публичные промпты, чаты, вложения и ключи провайдеров в файл синхронизации не включаются.

## Подключение

1. Создайте приватный репозиторий на своём GitHub. На Android и Desktop используйте один репозиторий и одну ветку.
2. Создайте fine-grained token для этого репозитория с разрешением **Contents: Read and write**. Вводите его в приложении, а не в переписке.
3. Desktop: **Настройки → GitHub**. Android: блок **Личные промпты · GitHub** в настройках.
4. Укажите `owner/repo`. Пустая ветка означает основную; после проверки приложение сохранит её фактическое имя.
5. Нажмите **Проверить изменения**. Просмотрите добавления, обновления и удаления. При конфликте выберите локальную версию или GitHub.
6. Нажмите **Применить синхронизацию**. Повторите проверку на втором устройстве.

Хранилище: `.aiprompts/personal-prompts.json`, общий формат обоих приложений. Файл создаётся после применения первой синхронизации. Текущий лимит — 900 000 байт UTF-8, до 10 000 записей. Изменения файла образуют обычную историю коммитов GitHub.

Это ручная синхронизация: сохранение обычного промпта не запускает публикацию в фоне. **Отключить GitHub** удаляет сохранённый токен и настройку подключения; локальные промпты и удалённый репозиторий сохраняются.

## Объединение и защита данных

- Первая синхронизация объединяет записи с разными ID. Разные версии одного ID требуют выбора.
- После синхронизации приложение хранит хеши общей версии. Изменения и удаления с одной стороны применяются к другой; одновременное изменение либо изменение против удаления требуют выбора.
- Перед записью повторно проверяется локальная библиотека. Обновление файла GitHub использует ожидаемый SHA; изменение удалённого файла после предпросмотра останавливает запись. Если запись не нужна, версия удалённого файла проверяется повторно перед применением.
- Пропажа ранее синхронизированного файла целиком останавливает синхронизацию. Она не считается командой удалить личную библиотеку.
- Локальная запись выполняется транзакцией Room. Совпадение ID с публичным каталогом отклоняется.
- Токен хранится в существующих защищённых настройках платформы, маскируется в поле ввода и исключён из текстового представления конфигурации. В запросах он передаётся заголовком, а не URL; перенаправления отключены.
- Формат нормализует даты, nullable-поля и порядок карт, сохраняет переменные, варианты, языки и метаданные. Это исключает различия, вызванные только платформенным преобразованием JSON.

Транспорт использует [GitHub REST Contents API](https://docs.github.com/en/rest/repos/contents).

## Debug-импорт и release

HTML-импорт и scraper доступны только в локальном Desktop debug: `-PdesktopBuildType=debug`. По умолчанию Desktop собирается в release. `DEBUG_MODE` из `local.properties` больше не управляет этой возможностью.

В release отсутствуют пункты импорта и scraper, запрещены переходы к ним, прежнее сохранённое состояние переводится к промптам. Автоматическое чтение файлов прежнего debug-импорта также отключено. В debug загрузка старых файлов выполняется однократно; синхронизация личного хранилища закрывает этот путь, чтобы удалённые записи не появлялись снова из резервных JSON.

Сборка MSI/EXE с debug-режимом отклоняется. Личная синхронизация GitHub, обычное создание промптов и обновление публичного каталога доступны в release. На Android HTML-импорта нет.

## Проверка реализации

- [x] Трёхстороннее объединение, конфликты, удаления и исчезновение файла.
- [x] Предпросмотр не выполняет удалённую запись; ошибки версии не изменяют локальную библиотеку.
- [x] HTTP через локальный сервер: приватность репозитория, Base64, SHA, ветка, отказ при конфликте и публичном репозитории.
- [x] Реальная Desktop Room: применение только к личным записям, защита публичных ID, отклонение устаревшего предпросмотра.
- [x] Android: круговое преобразование JSON → Room entity → JSON, миллисекунды ISO, варианты и определения переменных.
- [x] Визуальные проверки Desktop настроек при ширинах 360, 760 и 1440 без эмулятора.
- [ ] Реальный личный репозиторий: пользователь выбирает его и выполняет первое применение в приложении. Автоматических загрузок личных данных во время разработки не выполнялось.

## Android-чат

Общие параметры генерации подключены к Android. Температура, max tokens, top-p и размер истории сохраняются отдельно для каждого чата; несохранённые параметры и системный промпт восстанавливаются через SavedStateHandle.

Запрос включает текущий системный промпт и ограниченную историю без плейсхолдера ответа. Это исправляет прежнюю ситуацию, когда сохранённый системный промпт отсутствовал в запросе. Проверено тестами восстановления, сохранения и аргументов streaming-запроса.
