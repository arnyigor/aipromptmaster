# Единый адаптивный Android/Desktop UI

Решение от 30 сентября 2026: после стабилизации общего ядра постепенно перейти к общей Compose Multiplatform presentation с несколькими компоновками, выбираемыми по доступному размеру окна. Существующие интерфейсы сохраняются до переноса возможностей.

## Подтверждено в Android

`app/src/main/java/com/arny/aipromptmaster/ui/MainActivity.kt` использует `rememberMultiBackStackManager`, `HorizontalPager` для четырёх разделов и отдельный `NavDisplay` для стека каждого раздела. Нижнее меню переключает страницу через animateScrollToPage. Свайп обновляет выбранный раздел. Вложенные экраны ограничивают свайп через showBackButton.

Эту модель взаимодействия сохранить: независимая история разделов, свайп между корневыми разделами, возврат в ранее открытый экран. Реальное сохранение после process death нужно проверить отдельно в реализации менеджера и entry decorators; наличие multi-backstack само по себе его не гарантирует.

При анализе обнаружено: ModelsKey отсутствовал в начальной карте стеков, поэтому getBackStackFor возвращал новый временный стек при обращении. Добавлен постоянный стек Models и совместимое восстановление из сохранённых данных старой версии. Это исправление текущей Android-навигации, а не перенос UI на Desktop.

## Компоновки

| Доступная ширина | Представление |
|---|---|
| Менее 600 dp | Нижняя навигация, один экран, свайп разделов на корневом уровне |
| 600–839 dp | Navigation rail; одна или две панели с учётом высоты |
| От 840 dp | Постоянная боковая навигация, список и детали/редактор рядом |

Пороги — стартовая проектная модель, уточняем по реальному содержимому и доступной высоте. Большой Android-планшет получает широкую компоновку; узкое Desktop-окно — компактную. Размер окна не определяет OS и доступные функции. На Desktop компактная компоновка должна поддерживать мышь/клавиатуру, а на планшете широкая — touch.

Официальные правила: https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes

## Общая навигация и состояние

Один navigation/state owner выше переключаемой компоновки. Compact и Expanded принимают одно состояние и callbacks. Изменение размера окна не создаёт новый back stack, не теряет выбранный промпт, черновик, чат, scroll и позицию списка; сетевые операции не перезапускаются.

В широкой компоновке route «детали промпта» показывается во второй панели. При сужении эти же детали становятся отдельным экраном. Нажатие Back сначала закрывает вложенный экран/детали, а не произвольно меняет раздел.

Не хранить две независимые модели маршрутов для compact/expanded. Объединение Navigation 3 Android и Decompose Desktop — отдельное архитектурное решение после проверки их multiplatform APIs, сохранения state и обратного перехода. Сейчас один стек на другой не заменяется.

Источник сохранения navigation state: https://developer.android.com/guide/navigation/navigation-3/save-state

## Что унифицировать

Сначала модели UI, действия и общие компоненты: карточка промпта, содержимое, редактор полей, поиск, фильтры. Затем общий дизайн: typography, цвета, spacing и состояния загрузки/ошибок. Платформенные инструменты остаются адаптерами. Scraper/catalog curator tools доступны Desktop по capabilities, независимо от ширины окна.

Дизайн Android использовать как отправную точку компактной компоновки, существующие Desktop-возможности — как требования к широкой. Не удалять desktop импорт, классификацию, массовое редактирование и работу с файлами при визуальном объединении.

## Проверки перед переключением

- У каждого раздела независимый back stack; переключение не сбрасывает его.
- Свайп корневых разделов и клики меню выбирают один и тот же раздел.
- Resize compact→expanded→compact сохраняет детали, черновик, текущий чат и scroll.
- Свайп разделов не перехватывает горизонтальные жесты редактора/таблиц и вложенную навигацию.
- Android back/process recreation и Desktop keyboard/back работают предсказуемо.
- Проверены ширины по обе стороны порогов, маленькая высота и быстрые resize.

Переход выполнять экран за экраном после исправления импорта и выделения общего контракта, не одновременно с перемещением репозиториев.
