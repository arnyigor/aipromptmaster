# Общий контракт каталога — 2026-10-01

`prompt-contract` включён в оба Gradle roots. Все исходники и тесты находятся в commonMain/commonTest; сейчас используется JVM target, который потребляют Android и Desktop. Модуль не использует Android, Java API, Room или Compose. Отдельный Android target пока не нужен: модуль поставляет чистую библиотеку JAR, без платформенных ресурсов. Выходные файлы двух roots разделены, версии Kotlin берутся из каталога соответствующего клиента.

`CatalogContract.parse` проверяет исходные строковые ID и заголовок до coercion в клиентских DTO. `CatalogDocument` сохраняет JSON-поля, включая неизвестные расширения. `validateSnapshot` запрещает пустую загрузку и повторные ID, но разрешает одинаковые заголовки. Оба публичных ZIP-импорта используют эти проверки до записи в БД. Legacy ZIP по-прежнему не разрешает удалять отсутствующие записи.

Это первый этап пункта 6, а не завершённое объединение всех DTO. Android и Desktop пока сохраняют собственные адаптеры и доменные модели. Различаются переменные (Android: default_value; Desktop: обязательный type), варианты (Android: variant_id и priority внутри идентификатора; Desktop: variantId и отдельный priority), тип автора и даты. Эти поля нужно согласовать с опубликованным каталогом перед заменой адаптеров; автоматическое переименование могло бы потерять данные.

Проверки: common tests на неизвестные/variant-поля, недопустимые ID, пустые и повторные snapshot. CI запускает их в обоих roots вместе с проверками клиентов.
